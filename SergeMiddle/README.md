The iPlug2 VST3 for the middle section, built from the contract in the repository root (`README.md`, `IPLUG2.md`, `BUILD.md`). The root Python files stay the reference; this folder ports them.

## Layout

| Path | Role |
| --- | --- |
| `SergeMiddle.cpp`, `SergeMiddle.h` | iPlug2 plugin: Fold, IN 2 DC, the PLEAT plate, stereo or mono, `ProcessBlock` |
| `PleatView.h` | Plate, two skirted knobs, captions, rope cables. The audio path does not include it |
| `config.h` | Plugin identity, I/O, latency, window size |
| `CMakeLists.txt` | iPlug2 CMake project, format VST3 |
| `dsp/WaveMiddle.h` | Header-only port of `wave_middle.py`: cells, Lambert W, `DRIVE_PEAKS`, fold and IN 2 smoothers, IN 1 block, FIRs, output DC block, per-channel path |
| `dsp/WaveMiddleTables.h` | Generated by `tools/gen_tables.py` from `wave_middle.py` and the tap CSVs. Do not edit |
| `dsp/tests/` | Standalone C++ tests against the locked numbers. No iPlug2 needed |
| `resources/` | Plists, icons, Windows resources, Roboto, `pleat_plate.png`, `pleat_knob.png`, the `@2x` pair, `pleat_plate.svg`, and `pleat_knob.svg` |

iPlug2 is the `iPlug2` submodule at the repository root.

## Choices made here

`BUILD.md` names the project and the window. This folder is that choice.

- Project name: `SergeMiddle`. Unique ID `'Smid'`, manufacturer ID `'Mrsy'`.
- Window: 416 by 624. Two knobs sit on the plate. Fold is centered at (0.30 W, 0.38 H) and IN 2 DC is centered at (0.70 W, 0.38 H). Each knob has diameter 0.29 W. The plate bitmap is `pleat_plate.png` (the `@2x` file is 832 by 1248). It carries the panel lettering. The art sources are `pleat_plate.svg` and `pleat_knob.svg`, rasterized to the PNGs. The plate and knob PNGs are prototype art for the host test.
- Fold knob: 0.5 to 8, default 1, exponential taper so each octave of g gets the same travel. The number under the knob is the Fold display text. `ProcessBlock` reads that same `IParam` value. Projects saved before the Serge level change fold about half as hard at the same Fold setting. The same knob value now drives the cells with half the voltage, and Fold 2 matches the old Fold 1.
- IN 2 DC knob: -2.5 V to +2.5 V, default 0, linear, step 0.01 V, unit V. The parameter name is `IN 2 DC`. The original middle-section panel is VC, one knob, OUT, IN 2, and IN 1. The VCM kit sheet says IN 1 is coupled for AC only and IN 2 is coupled for DC. `ProcessBlock` reads that `IParam`, smooths it with the 20 ms one-pole, adds it at the 4× rate after the upsampler, and subtracts C^6(s) after the cells. The subtraction holds a silent input at exactly 0. On the hardware the AC-coupled output would instead show a decaying transient when that voltage jumps.
- IN 1 passes the same 10 Hz block before the drive, one state per channel, reset in `OnReset`. Each cell is non-inverting below the fold. Equation 31 of Esqueda et al. 2017 is Vout = 2 Vx - Vin, and Vx equals Vin while the diodes are off, so an inversion of IN 1 would have to sit in the input stage. That stage's schematic is not in the paper, and this port keeps the cell equation's polarity.
- Jacks on the plate: IN, IN 2, VC, OUT. IN is the audio input and OUT is the audio output. The captions and the cables are editor controls. `ProcessBlock` reads Fold and IN 2 DC.
- Reported latency: 16 samples. The two 63-tap filters delay 31 + 31 samples at the 4× rate, which is 15.5 audio samples.
- Formats: VST3. The macOS configure line is Unix Makefiles.

## Build the plugin

iPlug2 builds this plugin on macOS and Windows.

```text
git submodule update --init
cd iPlug2/Dependencies/IPlug && ./download-vst3-sdk.sh && cd ../../..
cmake -S SergeMiddle -B build/SergeMiddle -G "Unix Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build/SergeMiddle --target SergeMiddle-vst3
codesign --force --sign - build/SergeMiddle/out/SergeMiddle.vst3
```

On Windows, use `-G "Visual Studio 17 2022"` and run the download script from Git Bash. Skip the `codesign` line. The bundle is `build/SergeMiddle/out/SergeMiddle.vst3`. The `codesign` line is an ad-hoc signature so the Info.plist is bound.

The standalone APP compiles `resources/SergeMiddle-macOS-MainMenu.xib` with ibtool, so the format list is VST3.

## Test the DSP port (any platform)

```text
cmake -S SergeMiddle/dsp/tests -B build/dsp-tests -G "Unix Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build/dsp-tests
ctest --test-dir build/dsp-tests --output-on-failure
```

The tests read the root CSV files and `dsp/tests/chain_reference.csv`. They check:

- the embedded taps equal `halfband_taps.csv` and `upsample_taps.csv` bit for bit;
- `Process` matches `tests/transfer_g1.csv` within 1e-12 V, with exact odd symmetry;
- `audio_map` peaks at 1 for g in {0.5, 1, 1.2, 2, 3.3, 4, 8};
- the smoother coefficient and the 960-sample step;
- IN 2 at 0 V matches a legacy channel fed the DC-blocked input, bitwise, on a sine plus noise run. `Step(a, g)` matches `Step(a, g, 0)`. L and R match while IN 2 moves. A silent input stays exactly 0 at any IN 2. A +1 V offset raises |H2| / |H1| on the 86-cycle probe, and the IN 2 smoother tracks the 20 ms step;
- a 200 Hz unipolar triangle at g = 2 has |H2| / |H1| below 1e-3 after the IN 1 block settles, and a large ratio with that block bypassed;
- the decimator pass and stop probes, and the 1 kHz round trip inside the plugin path with the cells and the IN 1 block bypassed;
- a 20 Hz full-scale sine at g = 1 and at g = 2, with the IN 1 block bypassed, peaks within 0.001 of 1 before the output DC block;
- the 11.71875 Hz DC block figures, 1.109037 and 0.310004;
- the whole per-sample path (IN 1 block, smoother, upsampler, cells, decimator, bound, output DC block) against the Python reference within 1e-9.

## Regenerating

After a change to `wave_middle.py` or the tap CSVs:

```text
python3 tools/gen_tables.py
python3 tools/make_chain_fixture.py
```

`python3 tools/gen_tables.py --check` exits 1 when the header is stale.
